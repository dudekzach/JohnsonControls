Read This Before You Start

Three things that will break the demo if you find them out on the day.

1. Every phone number in the JCI mock data is a 555 reserved number

All the workbook numbers are in the 555-01xx fictitious range. An agentless campaign places real calls. If you import those as the dial column, the campaign will attempt, fail, and disposition every record as unreachable — and you will be debugging pacing when the problem is the data.

The generated contact list therefore carries Work_Phone = REPLACE_WITH_YOUR_TEST_NUMBER as the dial column, and keeps the JCI number in Reference_Phone as a display-only field. Substitute two or three numbers you actually control — your mobile, a softphone, a colleague who has agreed to answer — before import. Duplicating the same number across several records is fine and makes the dry run faster.

2. Agentless requires a Call Analysis Response Set containing a Transfer to Flow action

Genesys will reject a response set that transfers to agents, and it will equally reject one that has no Transfer to Flow action, because agentless depends on that action. Build the outbound flow before the response set, and the response set before the campaign. The order below is not arbitrary.

3. An Architect outbound flow cannot be created without a contact list and a default wrap-up code

Both must already exist. So the real build order is: wrap-up codes → contact list → outbound flow → call analysis response set → campaign. Steps 1 through 6 follow that sequence.

Demo value

Those last two mappings are the whole compliance story in two rows. When you show the wrap-up list in the session, the point is that a disposition on one call permanently changes who the campaign is allowed to dial — without anyone editing a list.

Step 2. Contact List and DNC List

Both CSVs are generated and attached. Twelve records, drawn from the JCI mock data.

What is in the contact list

Twelve sites taken from the should allow records in the JCI account mock data workbook — standalone fire and burglar systems only. COMBO records were deliberately excluded so the outbound story stays consistent with the band the inbound journey actually automates. That exclusion is itself a talking point.

Import

  1. Admin > Outbound > Contact Lists > Create New. Name it JCI Test Expiry Notification.
  2. Upload the CSV. Set Contact_ID as the ID column.
  3. Under Contact List Numbers, include only Work_Phone. Remove anything else the importer picks up.
  4. Set Time_Zone as the time zone column.
  5. In Column Data Type Specifications, mark Hours_Remaining and Max_Duration_Hours numeric, and Test_End_Date as a date.
  6. Confirm the record count is 12 and the import shows no errors. An import that partially failed makes the list unassignable to a campaign.

DNC list

Admin > Outbound > Do Not Contact Lists > Create New. Name it JCI Demo DNC and upload the DNC CSV.

Built for a specific beat

The DNC file contains the reference numbers for JCI-005 and JCI-012. If you choose to point your real test number at one of those records instead of leaving them on the placeholder, the campaign will visibly skip it — which is a much better demonstration of DNC than describing it. Decide which you want before import.

Step 3. Architect Outbound Flow

The notification itself. This is where most of the build time goes.

Architect > Flows > Outbound Call > Add — name it JCI Test Expiry Notification. You will be asked for a contact list (use Step 2's) and a default wrap-up code (use JCI — Message Left).

Outbound flows expose call.contact.<column> derived from the default contact list, so your CSV columns are available directly. Note that some Toolbox actions available in inbound flows are not present here.

Voice and persona

Match the POC: male, professional, business-like, reassuring. Do not use a cheerful assistant voice — this is a life-safety notification and the register carries meaning. Set the TTS voice at flow level so it is consistent across every prompt. verify which male voices are available in your org and pick the same family the POC build uses, so the two demos sound like one product.

Flow structure

Start
 └─ Set Participant Data          site=call.contact.Site_Name, cs=call.contact.CS_Number,
                                  ends=call.contact.Test_End_Local, notify_type="test-expiry"
 └─ Play Greeting  (TTS)
 └─ Menu  "Expiry options"        timeout 7s, 2 retries
     ├─ 1  Extend                 → Confirm → Set Wrap-up "JCI — Test Extended"
     │                              → Set Flow Outcome: Notification Accepted (Success)
     ├─ 2  No extension needed    → Confirm → Set Wrap-up "JCI — No Extension Needed"
     │                              → Set Flow Outcome: Notification Accepted (Success)
     ├─ 9  Do not contact         → Set Wrap-up "JCI — Do Not Contact Requested"
     └─ 0  Central station        → Set Wrap-up "JCI — Central Station Requested"
                                    → Transfer to ACD  [verify availability]
 └─ Timeout / no input x2         → Short close → Wrap-up "JCI — Message Left"
 └─ Disconnect

verify Two items to confirm in your org before you commit to the flow design: whether Transfer to ACD is available in an outbound flow (the opt-out-to-a-person branch depends on it — if not, replace with a callback request or a spoken number), and whether Flow Outcomes can be set in an outbound flow. If outcomes are unavailable, the reporting beat in Step 7 relies on wrap-up codes and campaign metrics alone, which is still sufficient.

Prompt text — copy directly

That test is scheduled to end at {{Test_End_Local}}. If work is still in progress, the system will return to normal alarm handling when the test ends."

Menu

No extension needed

TTS

Machine answer / no input

TTS

"This is an automated notification from Johnson Controls monitoring regarding the system test at {{Site_Name}}. That test is scheduled to end at {{Test_End_Local}}. If you need to extend it, please contact the central station. Thank you."

Do-not-contact confirmation

TTS

"This number has been removed from automated notifications. Thank you."

Two deliberate choices worth defending in the room

The notification never states a PIC, and never asks for one. It confirms a site and offers an action. Consistent with the inbound design, an authorisation decision does not happen over an unauthenticated outbound call.

Press 9 exists. A self-service opt-out that permanently marks the contact uncallable is the strongest single answer to a compliance question, and it costs one menu branch.

Publish the flow. It must be published before the response set can reference it.

The piece that makes an agentless campaign legal to save.

Do not carry the pacing warning across from the wrong context

Genesys documentation warns against transferring live voices to Architect flows because the flow answers everything immediately and destroys the pacing algorithm. That warning applies to agent-paced modes — progressive, power, predictive. Agentless has no agent pacing to disrupt, and Transfer to Flow is the intended mechanism. Worth knowing precisely, because if someone in the room has read that article you want to be able to explain the distinction rather than look caught out.

Step 5. Compliance Objects

Build these even though the campaign will run without them. They are the first thing you show.

Contactable time set

Admin > Outbound > Contactable Time Sets > Create New — JCI Notification Window.

  • Add an entry per time zone present in the list: America/New_York, America/Chicago, America/Denver, America/Los_Angeles.
  • Set each to a defensible window — 08:00 to 20:00 local, Monday to Saturday.
  • The campaign will refuse to save with a contactable time set assigned unless the contact list has a timezone column. Yours does.
Demo-day trap

If your session runs at 07:30 Mountain and the window opens at 08:00, the campaign will correctly dial nothing and you will look broken. Either widen the window for the demo, or — better — leave it as configured and use it as the point: "it's not dialling, and that's the control working." Then widen it live to prove the campaign responds. Decide which before you present, and rehearse it.

Attempt controls

Admin > Outbound > Attempt Controls. Cap attempts per contact and per number, and set a recall interval for busy, no answer, and machine outcomes. Modest values — two attempts, thirty minutes apart — keep the demo tidy.

Rule set optional

Admin > Outbound > Rule Management — JCI Notification Rules. One useful pre-call rule: skip records where Hours_Remaining is greater than 24, so only imminent expiries are dialled. This is a better demonstration than a contact list filter because it shows automation deciding, and it visibly excludes JCI-012 at 26 hours.

Step 7. Pre-build the Reporting

The closing beat fails if you are configuring a view live with an empty result set.

  • Run the campaign at least twice before the session so historical views have data. An empty Campaign Performance view is a worse ending than no ending.
  • Save a filtered Campaign Performance Summary view — dials, contacts, connect rate, abandon measures, campaign progress.
  • Save a Campaign Interaction Detail view so you can drill into a single attempt and show the wrap-up code that resulted.
  • If Flow Outcomes are available in outbound flows, save a Flow Outcome Performance view for Notification Accepted. verify
  • Have the inbound Test-On reporting open in an adjacent tab. The closing line depends on both being visible in the same analytics framework — that comparison is the whole point of the beat.

Step 8. Dry Run Checklist

Work through this at least a day before 9/11, not on the morning.

  • Placeholder dial numbers replaced with numbers you control, and the import shows 12 records with no errors
  • Reference_Phone is not configured as a phone number type
  • Test_End_Local and Test_End_Date refreshed to dates around the session — they are currently set to 9 and 10 September 2026
  • Live answer reaches the flow and the greeting says the right site name and end time
  • Press 1 completes, sets the extension wrap-up, and the record shows as terminated
  • Press 2 completes and dispositions differently from press 1
  • Press 9 marks the contact uncallable — verify in the contact list editor, not just the flow
  • Press 0 behaves as designed, or the substitute branch works if Transfer to ACD is unavailable
  • Machine answer or no input leaves the short message and dispositions as Message Left
  • A DNC-matched record is visibly skipped in the campaign results
  • Contact sorting puts the 2-hour record first
  • The rule set excludes the 26-hour record, if you built it
  • Caller ID displays the name and number you set
  • Campaign Performance and Interaction Detail views populate and are saved
  • Contactable time window is either widened for the session or rehearsed as the deliberate beat
  • TTS voice is male and matches the POC persona family
